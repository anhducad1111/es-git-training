# 実機確認手順書: GYRO PIDタブ（DEBUGタブに追加）

対象コミット: DEBUGタブに3つ目のタブ「GYRO PID」を追加。ESP32の
`/api/pid`（ジャイロ直進PID: kp/ki/kd/bias/enabled、および未検証の`turn`）を
見やすい大きめのUIで確認・変更できるようにした。SETTINGSタブの既存PID
コントロールは変更していない（両方から操作可能、最後に送った方が有効）。

変更ファイル: `views/debug_view.py` のみ。

## 事前確認（自動テスト済み・実機不要）

- `pytest tests/` 全件pass
- `RoverTeleopApp()` 生成時、DEBUGタブが `CALIBRATION` / `FOLLOW TUNING` / `GYRO PID` の3タブ構成になっていることを確認済み

## 実機確認手順

### 1. REFRESH（現在値の取得）

1. DEBUGタブ → `GYRO PID` を開く
2. `REFRESH (現在値を取得)` ボタンを押す
3. `kp/ki/kd/bias/turn`の各欄に、ESP32から返ってきた現在値が入ること、
   `ENABLED: ON`または`OFF`が実際の状態と一致することを確認
   （先ほどブラウザで確認した `{"kp":0.190,"ki":0.050,"kd":0.100,"enabled":true,"turn":0.40,"bias":0}` と一致するはず）
4. 下部のステータス欄に取得結果のJSONが表示されることを確認

### 2. APPLY（bias調整の実践）

1. `bias`欄を `10` に書き換える（他の欄はそのまま）
2. `ENABLED`ボタンがONになっていることを確認（OFFのまま送ると無効化されてしまう）
3. `APPLY (送信)` ボタンを押す
4. ステータス欄に「適用成功: {...}」が表示され、`bias`が10になっていることを確認
5. もう一度 `REFRESH` を押して、ESP32側に本当に反映されているか（`"bias":10`）を確認
6. DEBUGタブの `CALIBRATION` タブに戻り、前回と同条件（PWM200・1秒）で前進テストを実行し、右へのズレが減っているか確認
   （減らなければ`bias`を`15`,`20`と少しずつ上げて再テスト。左にズレ始めたら行き過ぎ）

### 3. 異常系

1. `car_ip`が間違っている、またはローバー未接続の状態でREFRESH/APPLYを押す
2. ステータス欄に「取得失敗: ...」「適用失敗: ...」が表示され、アプリがフリーズしないことを確認

## 問題があった場合

上記のどこかで期待通りに動かなかった場合、該当する手順番号と実際の挙動（ステータス欄の文言、ログパネルの内容）を教えてください。
