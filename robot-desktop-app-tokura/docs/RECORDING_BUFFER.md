はい、その通りです。30フレーム分の**一時バッファ**です。

```
カメラ映像 ──→ Queue(30) ──→ 録画スレッド ──→ AVIファイル
(Producer)      (Buffer)       (Consumer)      (Disk)

・Producer（カメラ）がフレームを追加
・Consumer（書き込みスレッド）が取り出してAVIに書き込み
・Queueがfullの場合、古いフレームを破棄して新しいフレームを追加
```

**なぜQueueが必要か:**
- カメラのフレームレート（15-30fps）と`cv2.VideoWriter.write()`の処理速度に差があるため
- 書き込みが遅れた場合、フレームをバッファリングしておき、その後まとめて書き込むことで安定した録画を実現
- **GUIスレッドを止めない**ために、書込み処理をバックグラウンドスレッドに委譲

**もしQueueが不要なら:**
- 書き込みが遅れた場合、フレームが失われる
- 書き込みが完了するまでGUIがブロックされる（フリーズ）

**結論:**
- 30は**バッファサイズ**で**録画上限**ではない
- RECボタンを押し続ける限り録画は続く
- Queueは一時的な**ストレージ**であり、保存場所ではない
- 最終的なAVIファイルは、REC停止時に**キュー内の全フレーム**が書き込まれる
